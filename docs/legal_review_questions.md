# 法務確認の問い合わせ資料（案）

専門家（弁護士・各国のプライバシー担当）に**何を確認したいか**を 1 か所にまとめた資料。基盤（chukore_kit）の現状の挙動と、止まっている作業、確認が済んだら何ができるかを書く。**ここに書いた法律・年齢の数字は私（実装者）の理解で、確認前の仮置き。専門家の回答で上書きすること。**

> **状況（2026-10-28）: 運営者の判断で、法務確認は行わない。** そのため、この資料の「確認が済んだら何ができるか」の機能は**有効にしない**（下の「法務確認なしで出す範囲」）。再開するときは、この資料をそのまま依頼に使える。

## 0. 法務確認なしで出す範囲

法務確認を行わない間は、**基盤が既定で止めている機能を、アプリで有効にしない**。基盤の既定は変えていない（送信の仕組みは無く、年齢の既定は安全側）。

| 機能 | 扱い |
|---|---|
| 回答履歴・点の記録・変化の表示 | **出す**（端末内で完結。本人にだけ見せる。送らない） |
| 匿名の報告・イベントの送信、匿名集計（`OutcomeReport`・`FunnelEvent`・`tallyOutcomes`） | **出さない**（送信の仕組みを作らない。ソフトローンチの測定は、ストア標準の指標と、端末内の確認で行う） |
| 範囲カードの QR 共有 | **出さない**（`ChildFeature.scopeShare` は既定で非表示のまま） |
| 13歳未満への通知・偏差値・成長カード共有・週次レポート | **既定のまま**（偏差値は出さない、共有とレポートは保護者ゲートのあと、通知は13歳未満に出さない） |
| 「使った人のうち◯%が点が上がった」などの訴求 | **使わない**（結果の保証と受け取られる表現は避ける） |
| 海外展開 | **日本のみ**（国ごとの子どもの個人情報の規制は、確認なしでは出せない。`RegionProfile` の暫定値を本番で使わない） |

アプリ側の注意: ストアの児童向け審査・データ申告（Google Play のデータセーフティ、App Store のプライバシー表示）は、法務確認とは別に**必ず**必要。

> 対象: 中学生（主に 12〜15 歳）向けの学習アプリ。基盤は**端末内で完結**し、通信・収集・送信をしない。収集や通知を行うのは各アプリ（`app_common_kit` の同意・保護者ゲートを使う）。

## 1. 基盤の現状の挙動（確認の前提）

| 機能 | 現状の挙動 | 根拠（コード/文書） |
|---|---|---|
| 回答履歴 | 端末内に保存（SQLite）。外へ出すのは、本人が書き出すバックアップ（`AttemptBackup`）だけ | `lib/src/store/` |
| 全削除 | `AttemptStore.deleteAll()`（SQLite は `VACUUM` まで）。書き出し済みのファイルは消せない | `docs/integration_app_common_kit.md` §4 |
| 年齢による機能の出し分け | `AgePolicy`（既定: 13 歳未満を子どもとして扱う）。偏差値は子どもに出さない、成長カードの共有・週次レポートは保護者ゲートのあと、範囲カードの共有は出さない | `lib/src/guardian/age_policy.dart` |
| 地域ごとの上書き | 地域コードごとに `AgePolicy` を JSON で差し替えられる（`AgePolicyTable`） | `age_policy_table.dart` |
| 通知の判定 | `decideNudge` は「出すかどうか」だけ判断。実際の通知（OS の許可・時刻・13 歳未満への可否）はアプリ側 | `lib/src/nudge/nudge.dart` |
| 保護者向けの内容 | 週次レポート・声かけの提案。個人情報（名前・メール）は入らない | `report.dart`・`guardian_talk.dart` |
| 匿名集計 | **未実装**。設計案のみ | `docs/anonymous_data_collection.md` |

## 2. 確認したい点

### A. 子どもの年齢の線引き（最重要）
1. 本アプリは**何歳未満を「子ども」として扱うべきか**。米国（COPPA）は 13 歳未満、EU（GDPR 第 8 条）は加盟国により 13〜16 歳、韓国は 14 歳未満、日本は法律上の年齢は無くガイドライン上の目安がある、というのが私の理解（**要確認**）。
2. 出す国ごとに線引きが違う場合、`AgePolicyTable` で**地域ごとに差し替える**運用でよいか。どの国で出すか（出さないか）の方針もあわせて。
3. 年齢の把握方法（生年月日の入力・年齢帯の選択・保護者による設定）は、収集する情報として許されるか。**生年月日は取らず、学年（中 1〜3）だけを聞く**案でよいか。

### B. 通知（`nudge`）
4. **13 歳未満（またはその地域の子ども）に、学習を促す通知を送ってよいか**。保護者の同意が要るか。要るなら、どの画面で・どう取るか（`app_common_kit` の同意の仕組みに載せる想定）。
5. 通知の文言は「責めない・数字を含まない」方針。このほかに、子ども向け通知で避けるべき表現（誘導・不安をあおる・連続記録の強調など）の基準はあるか。連続日数を促す通知（`nudgeStreak`）は、子ども向けでは不適切か。

### C. 回答の匿名集計（`docs/anonymous_data_collection.md`）
6. 送る項目（問題 ID・選んだ選択肢・正誤・モード・ヒント使用・学年）と、**送らない項目**（日時・所要時間・理由・自信・端末 ID・IP の保存なし）は、**個人情報・個人関連情報に当たるか**。当たらない（匿名加工情報・統計情報）と言える条件は何か。
7. 子どもの回答を集計に使うために必要な同意（保護者の同意か、本人の同意か）。**オプトイン・既定オフ**で足りるか。
8. 「すでに送った統計は取り消せない」（個人を結びつけない設計のため）ことを、削除の説明に書く形でよいか。削除請求（GDPR 第 17 条、個人情報保護法の利用停止等）への対応として、これで足りるか。
9. 集計サーバーの置き場所・運用主体、**越境移転**（海外のサーバーに置く場合）の扱い、保存期間（生ログは保存しない設計）。
10. ストアの申告（Google Play のデータセーフティ、App Store のプライバシー表示、Families ポリシー / Kids Category の要件）の書き方。子ども向けとして申告する場合、分析・広告 SDK の制限は。

### D. 保護者向けの機能
11. 保護者向けの週次レポート・声かけの提案を、**保護者ゲート（簡易な計算）の後ろ**に置く方針でよいか。ゲートの強度として十分か（米国 COPPA の「検証可能な保護者の同意」とは別の話として、閲覧の制限の位置づけ）。
12. 子どもの成績・偏差値に近い情報を保護者に見せる際の、表現上の注意（「全国の偏差値ではない」の表示は必須としている）。

### E. 共有機能
13. 成長カード（画像）・範囲カード（QR）の共有。画像に名前・ID は入らない設計。**範囲カードの共有は、確認が済むまで出さない**ことにしている（`ChildFeature.scopeShare` は hidden）。出してよい条件は何か。
14. 他アプリ紹介（`cross_promo_kit`）で外部ストアへ誘導する際の、子ども向けの要件（保護者ゲート必須としている）。

### F. 学習データの持ち出し・削除
15. バックアップファイルの扱い（名前・メールは入らない。回答履歴のみ）。ファイルを端末の外へ出すとき、本人・保護者への説明として必要な表示は。
16. アカウントを持たない設計（端末内完結）での、**データ削除の義務の範囲**（アプリのアンインストールで足りるか、アプリ内に削除画面が要るか。後者として `DataDeletion` を使う想定）。

## 3. 確認が済んだら進められる作業

| 作業 | 依存する確認 |
|---|---|
| `ConsentCategory.learningStats`（`app_common_kit`）と同意文言（18 言語） | A・C |
| `ChildFeature.dataSharing`（既定は不許可）と、送る束を作る関数（日時・所要時間・理由を落とす。テストで固定） | A・C |
| 匿名集計の受け口（サーバー）と、プライバシーポリシーの文言 | C |
| 子ども向けの通知の許可（`AgePolicy` に通知の項目を足す） | B |
| 範囲カードの共有を出す条件の実装 | E |
| 地域ごとの `AgePolicyTable` の初期値（出す国ごと） | A |

## 4. 確認の依頼のしかた
- 出す国（最初の 1〜3 か国）を先に決めると、確認の範囲が絞れる。
- 添付するもの: この資料、`docs/anonymous_data_collection.md`、`docs/integration_app_common_kit.md`、アプリの画面（同意・ゲート・削除）の案。
- 回答は、各質問に「可/不可/条件つき可」と条件を書いてもらい、`AgePolicy` や設計書に反映する。
