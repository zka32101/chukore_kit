# 全教科共通の学びの設計: 学ぶ・体験する・解く・評価する・分析する

> ステータス: 設計。レッスンの形式・検証・進み具合（§3）と `nextLearningStep`（§5）は実装済み、遊び・単元テスト・分析（§4・6・7）は未実装。決定済みの要望: **全教科で、①教科書のように学ぶ、②体験・遊びで学ぶ、③問題を解いて理解する、④テストで評価する、⑤データで分析する、を入れる**。今の基盤は ③④⑤が厚く、②は数学だけ、**①（学ぶ）がまだ無い**。この文書は、5 つを 1 本の「学びの流れ」にまとめ、足りない部品（特に①）と実装の順を決める。先に決めたいことは §8。

## 1. 1 つの単元の学びの流れ
```
      ┌──────────── 戻る（前提・つまずきの型の解説）────────────┐
      ↓                                                          │
  ①学ぶ ─→ ②体験する ─→ ③解いて理解する ─→ ④テストで評価する ─→ ⑤分析する
 （レッスン）（遊び・実験）（練習・復習・弱点）（単元テスト・模試）（本人・保護者・運営）
      ↑___________________ 弱点・復習・テスト日から次を決める ___________________↓
```
- 入口はテスト日（逆算）。そこから「今日やること」が決まり、**どの段階を出すか**は習熟度と誤解の型で決まる（§5）。
- 順番は固定しない。**得意な単元は ①② を飛ばして ③ から**、つまずいた単元は ③ から ① に戻れる。
- 責めない・結果を保証しない・順位をつけない（`docs/design_principles.md`）は全段階で守る。

## 2. 今ある部品と足りないもの
| 段階 | 今ある部品 | 足りないもの |
|---|---|---|
| ①学ぶ | 解説の ID（`explanationId`）、まちがいキャラ（誤答の解説）、前提グラフ（さかのぼり） | **レッスン（教科書のような説明・例題・要点）の形式、進み具合、確認クイズ（§3）** |
| ②体験・遊び | 数学の体験型（`Exploration`・作図）、問題の変種、まちがいキャラ（先生役）、成長の見える化（年輪・スタンプ・進化） | 他教科の体験、**遊びの形（ラウンド・連続・ごほうび。§4）**、キャラ収集（キャラ案待ち） |
| ③解いて理解する | 全問題タイプ、出題器（復習→重点→弱点→補充）、混ぜ練習、間隔反復、ヒント、疲れと休憩、変種 | 解き直しの「理解したか」の確認（§3.4 の事前・事後の確認） |
| ④評価する | 模試（`buildMockExam`・`scoreMockExam`・履歴・時間配分）、テスト後の振り返り、アプリ内偏差値、本番の点の変化 | **単元テスト・章テストの組み方（§6）**、合格ライン（できた・もう少し・復習）の見せ方 |
| ⑤分析する | 誤解の傾向、誤答選択肢の分析、難しさの補正、つまずきの根っこ、次の一手、匿名の効果測定（法務確認まで無効） | **レッスン・体験の効果の分析（§7）** |

## 3. ①学ぶ: レッスン（`Lesson`）
### 3.1 目的
教科書の「1 見開き」に当たる単位。**3〜5 分で読める**説明＋例題＋確認で、1 つの葉の単元の「分かる」を作る。説明の本文はコンテンツ側（国・言語ごと）、基盤が持つのは**構造・参照・進み具合・検証**。

### 3.2 形式（`lessons.json`、案）
```json
{
  "version": 1,
  "lessons": [
    {
      "id": "les_m1_linear_01", "version": 1, "unitId": "m1_linear", "minutes": 4,
      "blocks": [
        {"type": "hook",    "textId": "les_m1_linear_01_hook"},
        {"type": "text",    "textId": "les_m1_linear_01_t1"},
        {"type": "figure",  "figureRef": {"template": "fig_balance_01"}, "altId": "…"},
        {"type": "formula", "expr": "2x+3=11", "textId": "…"},
        {"type": "example", "template": "m1_linear_002", "seed": 7, "steps": ["st1", "st2", "st3"]},
        {"type": "explore", "exploration": "ex_linear_ab"},
        {"type": "check",   "questions": ["m1_linear_002~11", "m1_linear_002~12"]},
        {"type": "pitfall", "tag": "move_term_sign", "textId": "…"},
        {"type": "summary", "textIds": ["…", "…"]}
      ]
    }
  ]
}
```
| ブロック | 内容 |
|---|---|
| `hook` | 導入（なぜ学ぶか・身近な例）。1〜2 文。 |
| `text` | 説明。本文は `textId`（コンテンツ側の文言）。 |
| `figure` | 図（型の `figure` と同じ仕様か、型 ID＋種）。`altId` 必須。 |
| `formula` | 式の表示（`expr`。`MathExpr` で読めること）。 |
| `example` | **例題**。型 ID と種で問題を決め、`steps` で**途中式を 1 行ずつ**見せる（答えは型から計算した値と一致することを検証）。 |
| `explore` | 体験への入口（`Exploration`・作図の ID）。 |
| `check` | 確認クイズ 1〜3 問（問題 ID か変種 ID）。**答えを見る前に解く**。 |
| `pitfall` | つまずきの型の解説（`misconceptionTags` の型）。「ここで間違えやすい」。責めない文言。 |
| `summary` | 要点 2〜3 行。 |

### 3.3 検証（`validateLessons`）
エラー: `lesson_unit_missing`・`lesson_block_unknown`・`lesson_ref_missing`（問題・型・体験・図の参照先がない）・`lesson_example_mismatch`（例題の途中式の最後が型の答えと違う）・`lesson_example_step_break`（途中式の行が前の行と同値でない。段 6 の途中式判定を使う）・`lesson_tag_unknown`・`lesson_no_check`（確認クイズがない）。警告: `lesson_too_long`（`minutes` 5 超・ブロック 12 超）・`lesson_no_alt`（図に説明がない）。

### 3.4 進み具合と確認（端末内）
- `LessonProgress`: 読んだブロック、確認クイズの結果、**事前の確認**（レッスンの前に 1〜2 問。「知っていた」か）と**事後の確認**。事前→事後の伸び＝そのレッスンの効き目（§7）。
- 読んだだけでは**習熟度に加点しない**。確認クイズの結果だけを回答として残す（`Attempt` の `mode: lesson_check`）。体験・遊びも同じ（水増ししない）。

### 3.5 本文の作り方
基盤はレッスンの**本文を作らない**。コンテンツ側で、AI が下書き → 人が確認（指導要領・用語・やさしさ）→ 検証ツールで参照と途中式を確認、の流れ。数学・英語・理科の例題は型から機械で作れる（答えの食い違いが出ない）。

### 3.6 実装したもの（`lib/src/lesson/`）
- `Lesson`・`LessonBlock`（`hook`・`text`・`figure`・`formula`・`example`・`explore`・`check`・`pitfall`・`summary`）・`LessonSet.parse`（`lessons.json`。読めなければ `FormatException`）。`check` は 1〜3 問、`pre`（事前の確認）は 2 問まで、`summary` は 1〜4 行、`example` の途中式は 2〜12 行。**文言は ID だけ**（本文はコンテンツ側）。
- `validateLessons(set, tree:, refs:, checker:)`: §3.3 のコードのうち `lesson_unit_missing`・`lesson_unit_not_leaf`・`lesson_ref_missing`・`lesson_example_mismatch`・`lesson_formula_unreadable`・`lesson_tag_unknown`・`lesson_no_check`（エラー）、`lesson_too_long`・`lesson_no_summary`・`lesson_first_not_hook`（警告）。参照先の一覧 `LessonRefs`（問題・型・体験・作図・誤解の型）は教科側が作って渡す。教科ごとの検査は `LessonChecker`（例題の途中式・式の読み取り）で、数学は `MathLessonChecker(TemplateSet)`。
- **例題の検証**: 型 ID と種から変種を作り、途中式の行（`{a}x{+b}={c}` のように型の値を差し込む書き方）を描き出して `checkSolutionSteps` で 1 行ずつ確かめる。途中で式が変わる・目標に着かない・解の形まで整理していない・形（`form`）に合わない・**最後の行が型の答えと違う**、のどれかがあれば `lesson_example_mismatch`（どの行で何を間違えたかの誤解の型つき）。**例題の答えの書き間違いが、公開前に必ず見つかる。**
- `LessonProgress`（端末内。読んだブロック・事前の確認・確認クイズの結果・完了日時。不変で、更新は新しい値）、`isComplete(lesson)`・`preRate`・`postRate`・`gain`（事前 → 事後の伸び）・JSON の往復（読めなければ `FormatException`）。`lessonCheckAttempt` は確認クイズの結果を `Attempt(mode: 'lesson_check')` にする（習熟度には、ふつうの回答として数える。読んだだけ・体験だけでは加点しない）。
- `summarizeLessonEffects(progress, minLearners:)`: レッスンごとの記録の数・完了率・事前／事後の平均正答率・伸びの平均（§7「レッスンの効き目」の土台）。
- 見本: `docs/content_drafts/suugaku_chu1/lessons.json`（等式の性質・一次方程式の解き方・同類項・三角形の内角の和の 4 レッスン）。

## 4. ②体験・遊びで学ぶ
### 4.1 体験（教科ごと）
| 教科 | 体験の例 |
|---|---|
| 数学（実装済み） | スライダーで式を動かす、作図、天秤（`balance`。等式の性質のレッスンが参照） |
| 英語 | 語順を並べて文を作る（`order`）、文の穴を選ぶ、音声を聞いて選ぶ（TTS）、間違い探し（まちがいキャラ） |
| 社会 | 地図をなぞる（`map`）、年表づくり、因果の矢印つなぎ、時差ダイヤル |
| 理科 | 条件を変えて結果を見る（スライダーの `Exploration`: 力・電流・濃度）、実験の手順の並べ替え、観察の図選び |
| 国語 | 文を並べ替える・つなぐ、漢字の部品を組み立てる、言葉の分類 |
- 体験の仕様は教科共通の `Exploration` の種類を増やして持つ（`slider_graph`・`construction` に続き `balance`・`sort`・`link`・`dial`）。画面は教科アプリ側。
  - **実装済み**（`lib/src/experience/experience.dart`、教科共通・数学に依存しない）: `Experience`（`experiences.json`・`ExperienceSet.parse`・`validateExperiences`）の 5 種（`timeline` 年表づくりを追加: 置き方を「前後が逆の組」で返す）。`sort`（入れ物に仕分け: `check` → 正しい／違う／まだ）、`link`（点を矢印・線でつなぐ: 過不足）、`dial`（目盛を回して目標に: 許容つき）、`balance`（天秤: 傾き・つりあい・解の探索）。レッスンの `explore` ブロックからは体験の ID を `LessonRefs.explorationIds` に入れて参照する。

### 4.2 遊び（`PlayRound`、案）
**練習を遊びの形にする**だけで、問題と判定は③と同じ。
- 1 ラウンド＝5〜10 問。**連続正解の「つながり」**・小さなごほうび（スタンプ・成長カードの素材・キャラの進化）。速さで順位をつけない。残機・ゲームオーバーを**置かない**（責めない）。
- ラウンドの終わりに「今日のひとこと」と、弱点があれば**1 問だけ解き直しを提案**（強制しない）。
- 制限: ガチャ・順位・強制広告・時間ゲート課金は**置かない**（`docs/design_principles.md`）。子どもには保護者ゲートの外にあるものだけを出す。
- `PlayRound` の基盤の仕事は、ラウンドの組み立て（出題器＋混ぜ練習）、つながりの計算、ごほうびの条件の判定（純粋な関数）。見た目・音・アニメは画面側。
  - **実装済み**（`lib/src/practice/play_round.dart`）: `buildPlayRound`（練習の出題から 5〜10 問、単元を混ぜる）、`PlayProgress`（つながり・最長・立て直し。残機なし）、`finishPlayRound`（ごほうび `finished`/`link3`/`link5`/`comeback`、ひとこと `PlayClosing`、解き直し提案は 1 問）。

## 5. 「今日の学び」の決め方（`nextLearningStep`、案）
単元ごとの状態から、**次の 1 手**を決める（`buildDailyHome` に組み込む）。
| 状態 | 次の一手 |
|---|---|
| 未着手・前提が固まっている | ①レッスン（事前の確認 → 説明 → 確認クイズ） |
| レッスンを読んだ・習熟度が低い | ②体験があれば体験 → ③練習 |
| 習熟度が上がってきた | ③混ぜ練習・復習（間隔反復） |
| 同じ誤解の型を繰り返す | ①の `pitfall` ブロックに戻る → 解き直し |
| 前提が弱い | 前提の単元のレッスンへ（さかのぼり） |
| テスト日が近い | ④単元テスト・模試 → 失点の単元の復習 |
| 十分に固まった | 次の単元へ（`suggestNextUnits`） |
出力は `LearningStep`（`kind: lesson|explore|practice|test|review`、`unitId`、理由）。画面は理由をそのまま短い文にできる（責めない言い方）。

### 5.1 実装したもの（`lib/src/session/learning_step.dart`）
`nextLearningStep(now:, unitIds:, mastery:, attempts:, questions:, context:, testDate:)` → `LearningStep?`（範囲が空なら null）。材料は `LearningContext`（前提 `graph`・`lessons`・`progress`・単元ごとの `explorations`・やった体験 `doneExplorations`・単元ごとの復習の期限 `reviewDue`・しきい値 `LearningStepConfig`）で、省いた材料の段階は勧めない。**同じ入力なら同じ結果**。
優先順（上から）:
1. **テストが近い**（7 日以内）: 直近 3 日以内に模試（`mock`）・単元テスト（`unit_test`）を受けていなければ `test`（最も弱い単元と日数）。受けていれば新しいレッスン・体験を足さず、弱い単元の練習へ。当日はテストを勧めない（前日・当日のガードがあるため）。
2. **取り組む単元**: 仕上がっていない（習熟度 0.8 未満）単元のうち、記録のあるものの習熟度の低い順。記録が無ければ、前提が固まっていて取り組める新しい単元（`suggestNextUnits`）。全部仕上がっていれば `maintain`。
3. **前提が弱ければ土台へ**: 前提（習熟度 0.6 未満か記録なし）をさかのぼって、土台の単元を対象にする（`prerequisiteWeak`。循環があっても止まる）。
4. **同じ誤解の型の繰り返し**: 直近 30 日の誤答で同じ型が 3 回以上あり、その型の `pitfall` があるレッスンがあれば、**解説のブロックから**（`repeatedMistake`・`blockIndex`）。テストが近くても勧める。
5. **レッスン**: レッスンがあり、読み終えていなければ（習熟度 0.7 未満）。記録がまったく無ければ `newUnit`、あれば `lessonNotFinished`。テストが近いときは勧めない。
6. **体験**: レッスンのあとで（レッスンが無い・読み終えた）、習熟度 0.6 未満で、まだやっていない体験があれば（`afterLesson`）。
7. **復習・練習**: 復習の期限が来た問題が 3 問以上なら `review`、そうでなければ `practice`。
- `LearningStep` は `kind`（`lesson`・`explore`・`practice`・`review`・`test`・`maintain`）・`reason`・`unitId`・`lessonId`・`blockIndex`・`explorationId`・`tag`・`daysToTest`。**理由の文言は基盤に持たない**（教科アプリが責めない短い文にする）。
- `buildDailyHome(..., learning: LearningContext)` を渡すと `DailyHome.learningStep` に入る（今日の分が計画に無くても返す。範囲は `scopeUnitIds`、無ければ問題のある単元すべて）。
- しきい値は暫定（ソフトローンチで検証）。

## 6. ④テストで評価する
- **単元テスト・章テスト**: 模試（`buildMockExam`）の小さい版。範囲＝単元／章、問題数 5〜15、**誤解の型を満遍なく**（型のカバー）・難しさの配分（やさしい 3 : ふつう 5 : 難しい 2）を指定できる `buildUnitTest`。結果は 3 段階（できた／もう少し／復習しよう。点数・偏差値は子どもには出さず保護者に出す）。
  - **実装済み**（`lib/src/mock/unit_test.dart`）: `buildUnitTest`（5〜15 問・難しさ配分・誤解の型の優先・単元の偏りを避ける・やさしい→難しいの順・seed で再現）、`scoreUnitTest`（3 段階: 8 割以上／5 割以上／それ未満。履歴の mode は `unit_test`。誤答から誤解の型を数える）。入らなかった型は `missedTags`。
- 模試（既存）: アプリ内偏差値（海外は点・成績）、時間配分、履歴比較、テスト後の振り返り。
- テストの前は「やらないこと」ガード（前日・当日。実装済み）。結果は ⑤ へ、弱点は③の出題へ戻る。

## 7. ⑤データで分析する（端末内。送らない）
既存（誤解の傾向・つまずきの根っこ・誤答選択肢・難しさの補正・次の一手・本番の点の変化）に加えて:
- **学びの流れの分析**（`LearningFunnel`）: 単元ごとに、①→②→③→④の到達と離脱（どの段階で止まるか）。
- **レッスンの効き目**（`LessonEffect`）: 事前→事後の確認の伸び、確認クイズの正答率、読んだあとの習熟度の伸び。**効かないレッスンの特定**（コンテンツの直し先）。
- **ブロックごとの読まれ方**: 飛ばされる・戻られるブロック、確認クイズで多い誤解の型 → 説明の直し先。
  - **実装済み**（`lib/src/lesson/lesson_analysis.dart`）: `buildLearningFunnel`/`summarizeFunnel`（単元ごと・合計の到達と止まっている段階）、`summarizeBlockReads`/`skippedBlocks`（ブロックの読まれ方・飛ばされるブロック。「戻られる」は `LessonProgress` が読んだ集合だけを持つため未対応）、`lessonCheckMistakes`（確認クイズの誤答の型・解説の無い型）、`ineffectiveLessons`（伸びの小さいレッスン）。`LessonEffect` は既存。
- **体験・遊びの効果**: 体験した単元としていない単元の、習熟度の伸びの比較（本人内の比較）。
- **保護者向け**: 週のレポート（取り組んだ単元・つまずきの型・伸びたところ。数字より取り組みを話題に。既存の保護者への声かけ）。
- **運営向け（匿名・集計・最小件数あり）**: 同意と法務確認が済むまで無効（既存の匿名イベントの許可リスト＋最小件数のしくみに乗せる）。

## 8. 先に決めたいこと
1. **レッスンの長さと数**: 1 単元 1〜3 レッスン、各 3〜5 分（案）。中 1 数学（21 単元）で約 40 レッスン。
2. **動画は入れない**（案）。図・式・短い文・体験で説明する（容量・権利・作成コストのため）。
3. **レッスン本文の作り方**: AI 下書き → 人が確認（案）。確認の担当と基準（指導要領・用語・やさしさ）はコンテンツ側で決める。
4. **遊びの形**: 残機・順位なしの「つながり＋ごほうび」（案）。キャラ収集はキャラ案が決まってから。
5. **最初にレッスンを作る教科・単元**: 数学の一次方程式（型・体験・途中式が揃っている）（案）。
