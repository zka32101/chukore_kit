# 社会（中学）の基盤設計

> ステータス: 設計。`match`（§3.1）は実装済み、他は未実装。決定済みの発売順（英語 → 数学 → 社会 → 理科 → 国語。`docs/first_subject_decision.md`）の 3 番目。数学の基盤（`docs/math_foundation.md`）と同じ進め方で、**今ある部品で足りるもの・足りないもの**を洗い出し、足りないものを基盤に足す順を決める。先に決めたいことは §7。

## 1. 社会の特徴（数学・英語との違い）
- **知識の量が多く、国ごとに中身が違う**。そのまま出せる（数学・理科）教科ではなく、中身（地図・年表・用語）は `chukore_<国>_shakai` のコンテンツ側で持つ。基盤は**形式と判定と描画**だけ。
- **覚えるだけ**になりやすい教科。数学の「変種」の代わりに、**資料から読み取る**・**つなげる（因果・対応）**・**位置と時間の感覚（地図・年表）**を体験にする。
- **図・グラフ・地図が中心**。容量は数学より重い（`docs` のやりとり: 社会は中〜重）。画像でなく**ベクター**で持つ。
- 中学の社会は、1 年＝地理（世界と日本）＋歴史（古代〜中世）、2 年＝地理（日本の諸地域）＋歴史（近世〜近代）、3 年＝歴史（現代）＋公民。最初に出すのは**中 1 前半**（地理: 世界の姿・日本の姿・世界各地の生活と環境）。

## 3. 足りないもの

### 3.1 対応づけ問題（`match`）— 小さい
「人物と出来事」「国と首都」「時代と文化」を線で結ぶ。`answer` は `左ID:右ID` の組を `;` で区切る（`a1:b2;a2:b1`）。順不同・部分点は `multi` と同じ考え方（合った組 ÷ 全組。誤った組があれば減点）。`choices` は左右の ID の集合。検証: 組の数、左右の ID が選択肢にある、重複なし（`match_*`）。**実装済み**（`docs/question_bank_format.md`「対応づけ問題」）。

### 3.2 資料のグラフ（`chart`）— 中
雨温図（棒＝降水量、折れ線＝気温）、人口ピラミッド、円グラフ（割合）、棒・折れ線グラフ、統計表。数学の `Figure` に**グラフの要素**を足す:
- `figure.chart`: `{"kind": "bars|line|climate|pyramid|pie", "series": [...], "axes": …}`。値は型のパラメータ・数列（`{L}`）で作れるので、**資料から読み取る問題を変種にできる**（「最も降水量が多い月」「割合が最も大きいもの」）。固定の実データ（雨温図の気候区分当て）は、値をそのまま書く。
- 選択肢が図の問題（実装済み）と組み合わせる:「次の雨温図のうち、〇〇気候はどれ」。
- SVG は数学の図と同じ（`currentColor`・余白・XML エスケープ）。数値と軸の目盛りは値から作る。

### 3.3 地図データ（`MapPack`）— 中〜大
> **実装済み**（`lib/src/map/map_pack.dart`、`tool/validate_map.dart`、`tool/simplify_map.dart`）: `MapPack`（読み取り・書き出し。整数座標の差分符号化。出典必須）、`validateMapPack`（`map_*` のコード）、`simplifyMapPack`/`simplifyRing`（Douglas–Peucker・小さな島を落とす）、`renderMapSvg`。境界線のデータそのものはコンテンツ側。
> **GeoJSON からの変換**: `mapPackFromGeoJson`（`lib/src/map/geojson.dart`）・`tool/geojson_to_map.dart`。外側のリングだけを使い、丸め（既定 scale 1000）でできる重複・とげを除く。実データでの確認（Natural Earth 110m の世界の国 177 領域、小学コレ！社会の `world_countries.geojson`）: 変換だけで 102KB（目標 150KB 以下）、`validateMapPack` でエラーなし。**簡略化の注意**: Douglas–Peucker は位相を保たないため、許容誤差を大きくすると辺が交差することがある（世界では 0.05 度は問題なし、0.1 度でスーダン、0.2 度で西サハラも交差）。交差は `tool/simplify_map.dart` / `validate_map.dart` が報告する。世界は変換だけで容量に収まるので、簡略化は小さな許容誤差にとどめる。日本の都道府県は、国土地理院の利用条件（商用は利用報告が必要）を原典で確認してから同じ手順で変換する。
`map` の判定・描画はあるが、**データがない**。基盤が持つのは形式・検証・簡略化・SVG 出力:
- 形式 `map_packs/*.json`: `{"version":1,"id":"world_countries","bounds":…,"regions":[{"id","label","rings":[…]}], "attribution": "出典"}`。座標は経度緯度か、図法変換後の平面座標。**差分符号化（整数・差分）で容量を抑える**。
- 検証 `tool/validate_map.dart`: 領域 ID の重複、リングが閉じている、頂点数が少なすぎる・多すぎる（容量の目安）、自己交差、座標が範囲内、出典の記載。
- 簡略化 `tool/simplify_map.dart`（Douglas–Peucker。許容誤差を指定）。目標: 世界の国 1 枚 150KB 以下、日本の都道府県 1 枚 100KB 以下（簡略化後）。
- `renderMapSvg(pack, {highlight, labels})`（`Figure.toSvg` と同じ作法）。選択肢が図の問題（地図の部分の拡大）にも使える。
- **データの出典と権利**（コンテンツ側の確認事項）: 世界は Natural Earth（パブリックドメイン）、日本は国土数値情報（行政区域。出典表示が要る）を想定。**取得・利用条件は作業時に原典で確認する**（ここでは断定しない）。

### 3.4 年代・時差の計算 — 小
- 西暦と世紀の変換（`century = ceil(year/100)`）、年代の差、時差（経度差 ÷ 15、日付変更線）は、**式で書ける**。ただし式に `floor`・`ceil`・剰余が無い。`MathExpr` に `floor(…)`・`ceil(…)`・`mod(a, b)` を足す（数学の整数問題・データにも使える）。
- 時代区分 `EraTable`（`{"era":"弥生","from":-300,"to":250}`）: 年 → 時代を引く関数と、年表問題の「時代の前後」の検証。コンテンツ側の JSON。

### 3.5 体験型（覚えるだけにしない）
- **時差ダイヤル**（`slider_graph` の仲間 `dial`）: 経度を動かして現地時刻が変わるのを見る → 計算問題。
- **年表づくり**: 出来事カードを年表に置く（`timeline` の体験版。置き方の誤りを「前後」で返す）。
- **因果の矢印**: 出来事を原因 → 結果の順につなぐ（`order` の体験版。つなぎ方の誤りの型 `cause_effect_reversed`）。
- **資料を動かす**: 雨温図の降水量・気温を動かして気候区分の境目を知る（`Exploration` に `chart` を結ぶ）。
- いずれも習熟度に加点せず、体験後の確認問題で測る（数学と同じ）。

### 3.6 誤解の型（社会）
似た名前の取り違え（`name_mixup`: 源頼朝／源義経、聖徳太子／中大兄皇子）、時代の前後（`era_order`）、位置の取り違え（`neighbor_region`、`hemisphere_swap`）、単位・割合の読み違い（`percent_vs_count`）、用語の漢字違い（`kanji_homophone`: 摂政／接政）。**誤答選択肢は「取り違えやすい隣のもの」で作る**（同じ地方・同じ時代のもの）。

## 4. 容量
文字データは小さい。重いのは地図とグラフの数値（ベクターで小さく持つ）と、史料の画像（**当面、画像は入れない**。写真は権利と容量が重い）。方針: 地図 2 枚（世界の国・日本の都道府県）＋グラフは値だけ ＝ 合計で 300KB 程度を目標（簡略化後の実測で確認）。

## 5. 中 1 社会（日本）の単元草案（コンテンツ側）
地理: 世界の姿（六大陸と三海洋・緯度経度・時差・地図の見方）、日本の姿（領域・都道府県・地方区分）、世界各地の生活と環境（気候帯・雨温図・衣食住）。歴史: 古代（文明のおこり・縄文／弥生・古墳・飛鳥・奈良・平安）、中世（鎌倉・室町）。前提: 年表・地図の読み方 → 時代の流れ。作るのは基盤が揃ってから（`docs/content_drafts/shakai_chu1/`）。
