# ソフトローンチ 検証計画（暫定値を確定するために）

基盤の数値の多くは**作った人の見積もり（暫定）**。ソフトローンチ（少人数の先行公開）で、下の指標を見て確定する。**見るのは匿名の集計だけ**で、個人を追わない（回答を集める場合は [`anonymous_data_collection.md`](anonymous_data_collection.md) の同意と下限が前提）。

> 判断の原則: **数値を変える前に、変える理由になる指標と基準を決めておく**（結果を見てから基準を動かさない）。1つの値の変更は1回ずつ、版を分けて確かめる。

## 1. 暫定値と、見る指標

| 機能 | 暫定値（既定） | 何を見るか | 見直しの目安（案） |
|---|---|---|---|
| 休憩の提案 `BreakConfig` | 40分 / 連続誤答4 / 遅さ2.0倍 / 急ぎ 2秒×5回 / 再提案まで15分 | 提案の**表示数**、「休む」を選んだ割合、提案後30分以内の継続率 | 表示の8割以上が無視される→出しすぎ（閾値を緩める）。ほぼ出ない→厳しすぎ |
| ナッジ `NudgeSettings` | テスト7日前 / 毎日は3日前から / 復習3件以上 / 連続3日 / 間隔2日 / 14日で止める | 通知の**オフにされた割合**、通知後の開封→学習開始率 | 通知オフが増える→頻度を下げる（`minGapDays` を増やす） |
| 通知の時間帯 `suggestNudgeHour` | 学習開始の時間帯から提案 | 提案時刻に出した通知の開始率 vs. 固定時刻 | 差が小さければ複雑さを減らす |
| 克服判定 `isOvercome` | 直近3回連続正解・2日以上 | 克服後に**同じ型で再び間違えた**割合（戻り率） | 戻り率が高い→連続回数や日数を増やす |
| 復習の間隔 `ReviewConfig` | 1/3/7/14/30日 | 箱ごとの正答率（間隔を空けても答えられるか） | 箱3以降の正答率が6割未満→間隔を短く |
| 実測難易度 `calibrateDifficulty` | 20件以上・差0.15以上 | 判定された問題の割合と、版を上げたあとの実測のずれの縮み | ずれが多すぎる→基準値の作り方そのものを見直す |
| 誤答分析 `analyzeDistractors` | 30件以上・誤答の25%・5回 | 旗の付いた問題のうち、**人が見て本当に直した**割合 | 空振りが多い→割合を上げる／少なすぎ→下げる |
| 山場の予告 `findPeakAhead` | 3日先まで・1.5倍・5問差 | 予告が出た日の実施率（予告のない日との差）、予告後の前倒し | 差が無い→出さない判断もあり |
| ヒント `defaultHintCredits` | 1.0 / 0.7 / 0.45 / 0.25 | ヒント使用後の**次の同種問題の正答率**（ヒントで理解が進むか） | ヒント依存（使って、次も使う）が多い→段数や配点を変更 |
| 暗記カードの自己採点 | わからない/あやしい/わかった | 「わかった」と答えたカードの後日の正答率（自己評価のずれ） | 過信が目立つ→「わかった」の箱の上がり方を鈍く |
| アプリ内偏差値 | 誤差±5 | 偏差値の幅と、実際の学校の模試・定期テストとの**本人の自己申告の差**（任意） | 幅が実際の揺れより小さい→幅を広げる。**全国の偏差値ではない表示は変えない** |

## 2. 全体の健全性（数値ではなく「やめる」の兆し）

- 学習の継続（7日・14日・30日）。ただし**長く使わせること自体を目標にしない**（休憩・日々の上限の方針と矛盾させない）。
- 保護者の週次レポートの開封と、そのあとの子どもへの声かけの有無（任意のアンケート）。
- 「つらい」「多すぎる」の声（問い合わせ・レビュー）。山場・ナッジ・休憩の文言と頻度の見直しの根拠にする。
- 自己申告の理由（`LossReason`）の回答率。**答えなくてよい設計**なので、低くても失敗ではない。答える子が少数なら、推定（`classifyMistakes`）の精度を別に確かめる。

## 3. 進め方

1. **前提**: 回答の匿名集計の同意・下限・サーバーを用意（なければ、端末内の集計だけで見られる指標〔休憩・通知・克服の戻り率〕から始める）。
2. **期間**: 最初の2週間は**値を変えない**（ベースラインを取る）。
3. **変更**: 週に1つ、1つの値だけ。変更前後で同じ指標を比べる。
4. **下限**: 1つの判断に使う集計は、**ユーザー30人以上・問題あたり30件以上**（`analyzeDistractors` と同じ）。足りなければ「まだ判断しない」と記録する。
5. **記録**: 変更した値・日付・理由・結果を、`docs/` に追記する（版の履歴と対応させる）。

## 4. 値と無関係に、先に確認すること

- [ ] 18言語のネイティブ確認（[`native_review_checklist.md`](native_review_checklist.md)）と、実機のフォント確認。
- [ ] 文字拡大200%・RTL（アラビア語）・色覚（[`accessibility_colors.md`](accessibility_colors.md)）の実機確認。
- [ ] 法務確認（13歳未満の通知・表示・各国の年齢規定、データ収集）。
- [ ] ストアの掲載文・データ申告（Google Play ASO ルール）。
