# 色のアクセシビリティ（配色の検査）

色だけで意味を分けない（形・文字・読み上げも付ける）のが基本。そのうえで、配色を機械的に確かめる道具が基盤にある。

## 道具

| 関数 | 用途 |
|---|---|
| `contrastRatio` / `meetsTextContrast`（4.5・大きな文字 3）/ `meetsGraphicContrast`（3） | 背景との明暗の差（WCAG AA） |
| `simulateColorVision(色, ColorVision.protan / deutan / tritan)` | P型・D型・T型での見え方の近似（Machado 2009、完全型） |
| `colorDifference(a, b)` | 見た目の違い（CIE76 ΔE。10 未満は区別しにくい、20 以上ははっきり） |
| `confusablePairs(配色, ColorVision.deutan)` | 配色のうち、その見え方で区別しにくい組（空なら OK） |

アプリの配色を決めるとき・変えるときは、**P型・D型の両方**で `confusablePairs`（`minDelta: 20`）が空になるか、色だけで意味を分けている組が無いかを確かめる。

## 現在の扱い

- 正解（緑）と不正解（赤）: D型・P型では近く見える（テストで固定）。そのため**✓ / ✗ のアイコンと読み上げ**を必ず付ける（地図・年表・当日チェック。`accessibility_test.dart`）。形の手がかりを外すなら、先に配色を変える。
- 既定の教科色（`0xFF3B82F6`）: 白地で約 3.68（図形には使えるが小さな文字には使わない）。
- 教科ごとの色: アプリ側が決める。**5教科の色を決めたら、全部の組を `confusablePairs`（P型・D型・T型）で検査する**（色だけでなく教科名も必ず併記する）。

## 限界（未実施・注意）

- シミュレーションは**近似**で、実際の見え方には個人差がある（軽度・中等度もある。完全型は最も厳しい想定）。
- ΔE は CIE76（簡易）。厳密な判断が要るときは CIEDE2000 などに替える。
- **実機・実際の色覚の人による確認は未実施**。リリース前に、できれば当事者の確認を受ける。
- 画像（教科書の図、地図の色分け）には使っていない。図の色分けにも同じ検査をかけること。
