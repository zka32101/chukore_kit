# オフライン対応の設計（通信が弱い・高い国でも使える）

> ステータス: 方針を決定（2026-11-02 運営者）。教育格差を減らす方針で、通信が不安定・データが高い国でも使えるようにする（[`country_priority.md`](country_priority.md) §5）。

## 1. 約束
1. **勉強の中心は、通信なしで最後まで動く**。問題を解く・解説を読む・レッスン・図・遊び・成長（相棒・図鑑）・復習・計画・振り返り。
2. **初回起動から**オフラインで使える。最初に必要な内容は、アプリに入れておく（ダウンロードを待たせない）。
3. 通信が必要なものは、**後回しにしても勉強を止めない**（失敗しても、仮の絵・前の版のまま続ける）。
4. 通信するのは**取得（GET）だけ**が基本。子どもの情報を送らない（基盤はデータを集めない・送らない）。
5. データ通信量が高い国を想定し、**Wi-Fi のときだけ・任意**にできる。大きなダウンロードは、必ず本人（保護者）の操作か、Wi-Fi のとき。

## 2. オフラインで動くもの／通信が要るもの
| オフラインで動く（基盤が保証） | 通信が要る（アプリ側。任意・後回し可） |
|---|---|
| 問題の出題と採点（型から変種を端末で作る。`MathTemplate`） | 内容パックの更新（新しい単元・直した問題） |
| レッスン・解説・図・動く図・証明・体験 | 画像のダウンロード（`ensureArt`。無効や失敗でも仮の絵） |
| 計画・復習の間隔・単元テスト・分析 | 購入・課金の確認（初回と更新時） |
| 相棒の成長・進化・図鑑・スタンプ・バッジ | バックアップ・端末の引き継ぎ |
| 成長カード・振り返り・テスト後の入力 | 通知（OS のプッシュ） |
- 基盤（`lib/`）は**ネットワークを使うライブラリを一切持たない**（`dart:io`・`package:http` などを使わない）。通信は、アプリが実装する入口（`ArtFetcher` など）だけ。これを**テストで固定**した（`test/offline_test.dart`）。

## 3. 内容パックの届け方（オフライン前提）
- **国の最初の教科（例: 数学）のパックは、アプリに同梱する**。数学の中1〜中3の草案は約 310 KB（JSON）と小さい。初回から全機能が使える。
- パックの更新は、**起動時に版だけ確認**（数バイト）。新しい版があるときは、Wi-Fi のとき・任意でダウンロードし、**ハッシュと大きさを確かめて**から入れ替える。失敗したら、前の版のまま。
- 版を上げるときは、**古いデータ（学習記録）が読める互換**を守る（設計方針 §2-7）。
- 2 教科目以降は、**教科ごとに別アプリ**なので、それぞれが自分のパックを同梱する（国をまたいで共有しない）。

## 4. 画像（相棒・分野キャラ・スタンプ）
- 最低限の画像は**アプリに入れる**（`bundled`）。通信が弱い国ほど多めにする。見本では、はじめの相棒の「たまご」だけを同梱しているが、**オフライン中心の国では、各相棒の序盤の数段階を同梱**する。
- 残りは任意のダウンロード。なくても**仮の絵**で全機能が使える。ダウンロードは Wi-Fi のとき・任意。
- 画像のサイズは小さく（上限 2 MB、実際は数十 KB を目標）。形式は svg・webp を優先。

## 5. 低価格の端末
- 古い OS・少ないメモリ・小さい容量でも動く。アプリのサイズは、国の最初の教科で**目標を決めて守る**（案: インストール 30 MB 以下。実測してから決める）。
- 図は端末で描く（画像でなく、数値から描く図）ので、画像の容量が増えない。
- 時刻・時差は端末の時計を使う（`Clock`）。端末の時計が狂っていても、成長・復習が壊れない（増えるだけの設計）。

## 6. 課金（オフライン）
- 課金の確認は通信が要る。**一度確認できたら、端末に保存して、オフラインでも使える**期間を決める（案: 猶予期間を長めに）。切れたとき、勉強を止めずに「無料の範囲」で続けられる。
- カード以外の決済（キャリア決済・モバイル決済・プリペイド）を想定（国ごとに法務・決済の確認）。時間で急がせる課金はしない。

## 7. 確かめること
1. 国の最初の教科の同梱パックの実サイズ（画像込み）と、アプリの目標サイズ。
2. 画像をどこまで同梱するか（段階ごとの小ささ）。
3. 課金のオフライン猶予の長さと、切れたときの無料の範囲。
4. 低価格端末での実機確認（動作の軽さ、フォント、文字拡大 200%）。
